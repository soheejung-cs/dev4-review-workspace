# 모델·추론 강도 선택 규약

하네스 작업을 여러 에이전트로 쪼갤 때 **어느 단계를 낮추고 어느 단계를 유지하나.**
사용자 결정 2026-09-21: **"수집은 강등, 판정·종합·반증은 유지, 애매하면 올려보낸다."**

## 왜 "요청 종류" 가 아니라 "판단이 섞여 있나" 인가

"코드 리뷰는 높게, 잡무는 낮게" 로 가르면 **잡무로 분류될 것들이 실제로는 판단을 품고 있다.**
2026-09-21 한 세션에서 나온 반례:

| 요청 | 겉보기 | 실제로 걸린 판단 |
|---|---|---|
| `/agent-board` | 카드 코멘트 + worklog 한 줄 | 닫힌 카드에 `in-progress` 라벨이 남은 것을 발견 → 이 보드의 관행인지 다른 카드로 확인해야 했다 |
| `/post-merge 7976` | develop ff + 정리 | `현황.md` 를 다른 컨테이너가 먼저·더 자세히 써 둠 → **내 커밋을 버리는 판단** |
| CI 실패 분석 | 로그 읽기 | 답은 로그가 아니라 **두 런의 러너 이름이 같은 세트**라는 대조에서 나왔다 |
| `/pre-clear` | 체크리스트 | "이 goto 캐시를 지워도 되나" 가 매번 섞인다 |

그래서 축은 **요청의 이름이 아니라 그 단계가 하는 일**이다.

## 단계 등급

| 등급 | 하는 일 | 예 | 지정 |
|---|---|---|---|
| **수집** | 이미 있는 것을 가져온다. 정답이 문서·코드·API 에 있고, 틀리면 다음 단계가 알아본다 | grep·파일 열기·서지 확인·GitHub API·로그 필터·목차 추출 | `{effort: 'low'}`, 필요하면 작은 모델 |
| **변환** | 형식을 맞춘다. 내용 판단이 없다 | 표 만들기, 링크 정리, 일괄 치환, 파일 이동 | `{effort: 'low'}` |
| **판정** | 무엇이 맞는지 정한다 | 이게 결함인가, 어느 안을 택하나, 어느 ID 로 지적하나 | 기본값 유지 (지정하지 않는다) |
| **종합** | 여러 조사 결과를 합쳐 결론을 낸다 | 비교표, 최종 보고서, 우선순위 | `{effort: 'high'}` |
| **반증** | 앞 단계를 무너뜨리려 한다 | 오탐·미탐 찾기, 실재 검증 | `{effort: 'high'}` |
| **메인 루프** | 사용자와 대화하며 결정한다 | — | **절대 낮추지 않는다** |

`agent()` 의 `model` 은 **확신이 있을 때만** 준다. 없으면 생략해 세션 모델을 물려받는다(워크플로 저작 레퍼런스 규약).
`effort` 는 단계 성격이 분명하므로 위 표대로 준다.

## 올려보내기 (escalate) — 이게 없으면 강등은 위험하다

강등의 실패는 **조용하다.** 약한 모델이 보드를 갱신하면 에러가 나는 게 아니라 worklog 한 줄이 부실해질 뿐이고,
아무도 모른다. `repro_obligation` 의 조용한 강등(2026-09-21 수정)과 같은 종류다.

그래서 **수집·변환 단계의 스키마에 탈출구를 박는다**:

```js
const COLLECT = {type:'object',
  properties:{ result:{type:'string'},
               needs_judgment:{type:'boolean'},   // 판단이 필요하다고 스스로 판정
               why:{type:'string'} },             // 무엇이 애매한가
  required:['result','needs_judgment']}

const found = await agent(prompt, {effort:'low', schema: COLLECT})
if (found.needs_judgment) {                        // 그 항목만 판정 단계로 올린다
  await agent(`아래를 판정하라 — 수집 단계가 애매하다고 올렸다: ${found.why}\n\n${found.result}`,
              {effort:'high'})
}
```

프롬프트에 **무엇을 올려보내야 하는지** 명시한다 — "규약이 서로 어긋난다 / 근거를 못 찾았다 /
둘 중 무엇이 맞는지 모르겠다 / 사실과 문서가 다르다" 면 `needs_judgment: true`.

## 조용한 실패를 막는 보고

워크플로가 끝나면 **낮춘 단계 수와 올려보낸 수**를 `log()` 로 남긴다.
올려보낸 수가 0 이면 좋은 게 아니라 **탈출구가 안 도는 것일 수 있다** — 수집 단계가 전부 자신만만하면 의심한다.

## 하지 않는 것

- 판정·종합·반증을 비용 때문에 낮추지 않는다. 이 하네스의 값어치는 거기서 나온다.
- 사용자와 대화하는 메인 루프를 낮추지 않는다.
- `model` 을 근거 없이 지정하지 않는다 — 생략이 기본값이다.
