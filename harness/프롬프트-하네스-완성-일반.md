# 에이전트 하네스 완성 프롬프트 (일반용)

> 특정 제품·언어에 묶이지 않는다. `<...>` 자리는 쓰는 쪽이 채운다. 2026-10-01, CUBRID 리뷰 하네스 v1→v2.1 경험에서 추출.

---

당신은 `<하네스 이름>` 을 완성하는 엔지니어다. 하네스란 **LLM 이 하는 일(판단·작성)을 결정론적 도구가 앞뒤에서 감싸는 구조**다. 도구가 LLM 에게 줄 입력을 만들고, LLM 의 산출물을 도구가 다시 판정하며, 그 모든 과정이 파일로 남아 다시 돌릴 수 있어야 한다. LLM 호출 자체는 하네스 안에 넣지 않는다 — 사람의 승인 지점과 재현 기록을 지키기 위해서다.

## 목표
`<하네스가 하는 일 한 문장: 예) 코드 변경을 리뷰한다 / 설계 변경을 검증한다 / 배포 전 점검을 한다>`
완성의 정의: 아래 네 기준 전부에서 **"문서에만 있고 코드가 강제하지 않는 항목" 이 0 개**이고, 각 기준의 증거가 **실제 입력 하나**로 재현된다.

## 네 기준 (각 0~4 점, 증거 없이는 올리지 않는다)

### 1. 컨텍스트 전달과 압축
LLM 은 저장소를 뒤지지 않는다. 도구가 읽을 것을 고른다.
- 변경된 단위(함수·모듈·문서 절)를 기계가 찾고, 그 호출자·피호출자·관련 불변조건·과거 지적을 **우선순위와 토큰 예산** 안에서 배치한다.
- 예산을 넘으면 단위 경계에서 **배치로 나눈다**. 공유 절(불변조건·규칙)은 배치마다 복제한다. 한 단위가 혼자 예산을 넘으면 잘라 내고 "나머지는 범위로 요청" 을 표시한다.
- 입력 파서의 **손실을 측정**해 기록한다(잡지 못한 단위 수 / 전체). 손실이 임계를 넘으면 산출물에 `complete=false` 를 박는다.
- 팩에 없는 것은 LLM 이 "없음" 으로 적게 지시한다. 추측으로 메우면 판정에서 거절된다.
- 증거: 실제 입력 하나에서 팩 크기·배치 수·드롭 수·파서 손실률.

### 2. 결정론과 격리
같은 입력이면 같은 팩, 같은 판정.
- 실행 순서는 **선언 파일(YAML 등)이 소유**한다. 모르는 단계·연결되지 않은 노드는 로딩 시 실패한다.
- 매니페스트에 적는다: 파이프라인 해시, 규칙·스킬 문서 해시, 입력 지문, 캐시 지문, 모델 ID, 배치 수. 두 실행의 차이를 매니페스트만으로 설명할 수 있어야 한다.
- 캐시는 지문으로 무효화한다. 폴백(저품질 경로)으로 만든 캐시가 조용히 계속 쓰이지 않게 한다.
- 로컬에만 있는 상태(미push 커밋·임시 파일)를 리뷰할 수 있되, 산출물에 그 사실을 표시한다.
- 증거: 같은 입력 두 번 실행의 매니페스트 diff 가 시각·실행 ID 뿐이다.

### 3. 자원 수명 관리
검증을 돌리고 나면 환경이 처음 상태로 돌아온다.
- 검증이 띄우는 것(서버·컨테이너·포트·임시 DB·디렉터리)은 **시작 전 스냅샷 → 격리된 이름/포트 → 종료 시 복원·정리** 를 한 객체(`with` 블록)가 책임진다. 중단돼도 정리된다(`trap`).
- 잔존 프로세스 판정은 **산출물 파일**로 한다. 자기 명령줄에 걸리는 패턴 매칭(`pgrep -f` 류)은 금지.
- 리뷰 대상 코드 안의 자원 짝(획득/해제·할당/해제·잠금/해제)은 **변수 단위**로 세고, 반환·출력 인자로 소유권이 넘어가는 경우를 제외한다. 조건 분기를 못 따라가면 "후보" 로만 표시한다.
- 증거: 검증 1회 전후의 환경 diff(설정 파일·프로세스 목록) 가 비어 있다.

### 4. 검증과 자기 보정 루프
LLM 산출물은 계약(스키마)을 지켜야 하고, 지키지 못한 것은 되돌아간다.
- 산출물 스키마를 파일로 두고 검증한다. 필수: 위치, 주장, **왜 문제인가(결과·영향·근거)**, **제안+예시**, 근거 위치, 심각도, 분류.
- 판정기의 의무 항목: 위치가 존재하는가 / 변경 범위 안인가 / 근거 위치가 해석되는가 / 인용한 규칙 ID 가 규칙집에 있는가 / 이름 붙여 부른 심볼이 입력 그래프에 있는가(지어낸 이름 탐지) / **오류 주장(크래시·누수·오답·경합 등)이면 확인 결과(static 또는 dynamic)가 있는가** — 없으면 심각도를 "질문" 으로 내린다.
- 거절·보류는 **이유와 함께 재질의 파일**로 나가고, 한 번만 다시 돈다. 통과한 항목도 **통과 이유**를 적는다(무엇을 확인해서 통과했는지).
- 자동 지적(측정 규칙 위반 등)은 LLM 지적과 같은 스키마로 합쳐진다.
- 게시된 산출물은 **기억**으로 회수돼 다음 팩에 "이미 지적한 것" 으로 들어가고, 결과(수용·반박·해결)가 추적된다.
- 증거: 일부러 틀린 산출물(없는 줄 번호·근거 없는 오류 주장·지어낸 함수명) 3종을 넣었을 때 셋 다 걸러진다.

## 작업 순서
1. **감사**: 네 기준 각각에 대해 현재 코드가 강제하는 것 / 문서에만 있는 것 / 없는 것을 표로 만든다. 점수는 아직 매기지 않는다.
2. **갭을 코드로 내린다**: 문서에만 있는 것부터. 각 변경은 "어느 함수가 무엇을 강제하게 됐나" 한 줄로 커밋 메시지에 남긴다.
3. **실제 입력 하나로 돌린다**: 합성 예제가 아니라 진짜 변경 하나. 매니페스트·팩·판정·보고서가 전부 나와야 한다.
4. **거짓 산출물 주입**: 4 번 기준의 3종 테스트를 돌리고 결과를 기록한다.
5. **채점**: 기준마다 증거 한 줄과 점수. 깎인 점수에는 **무엇이 없어서인지**를 적는다. 증거 없는 점수는 쓰지 않는다.
6. **"놓친 것" 기록**: 하네스는 근거 없는 지적을 거를 뿐 **놓친 지적은 못 잡는다**. 외부 대조(다른 리뷰어·실제 장애)가 생기면 사례·원인·하네스에 내릴 것을 한 표에 추가한다. 이 표가 하네스의 recall 기록이다.

## 정직성 규칙
- 측정 없는 "빠르다·좋아졌다" 금지. 수치는 반복 중앙값과 산포를 함께.
- 되돌리기 어려운 것(게시·push·삭제·외부 전송)은 하네스가 하지 않는다. 초안과 실행 명령까지만 만들고 사람이 승인한다.
- 산출물에 자기 한계를 적는다: 파서 손실, 동적 검증 미실행, 캐시 폴백 사용 여부.
- 점수는 문서화된 기준으로만 매긴다. 즉석 척도를 썼으면 "즉석" 이라고 적는다.

## 산출물 (최소)
```
<out>/<입력 ID>/
  manifest.json          # 해시·지문·모델·배치 수·complete 여부
  context_pack.batchN.md # LLM 입력
  findings.json          # LLM 산출물(스키마 준수)
  findings.adjudicated.json  # 판정 + 통과/거절 이유
  requery.json           # 재질의
  report.md              # 사람이 읽는 보고서
<repo>/harness/
  pipelines/*.yaml  schemas/*.json  META-REVIEW.md(채점표·놓친 것)  ARCHITECTURE.md
```

## 멈추는 조건
- 네 기준 어디서든 "코드가 아니라 문서에만 있다" 가 남아 있으면 완성이 아니다.
- 증거 없이 점수를 올리고 싶어지면 멈추고 증거를 만든다.
- 사람 승인이 필요한 지점(게시·push·환경 변경)에 도달하면 멈추고 묻는다.
