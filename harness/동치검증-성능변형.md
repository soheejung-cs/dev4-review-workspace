# 성능 변형의 동치 검증 — perf → 변형 → CBMC

사용자 지시(2026-11-20 .50): C/C++ 성능 작업에 "병목 추출(perf·Cachegrind·LLVM-MCA) → LLM 의 코드·IR 변형(SIMD·AoS→SoA 등) →
동치성 검증(Alive2·CBMC, 실패하면 반례를 LLM 에 되돌림)" 파이프라인을 하네스에 넣는다. 결정: **CBMC 먼저**(Alive2 는 뒤에),
**성능 변형일 때만 필수**. 2단계의 'LLM Compiler' 는 따로 들이지 않는다 — 변형은 구현 하네스의 LLM(이 세션)이 쓰고, 그 결과를
3단계가 기계로 증명한다.

자리: `harness-implement` S1.5(구조 먼저) → S3(구현) 사이의 **S3.5**. 게이트 `implement_gate` (5-1) 이 강제한다.

## 1. 병목 추출 — 무엇을 변형할지
- 시간 지도는 그대로 `tools/perf/perf_attach.sh` + `prof_bucket.py`(structure.json `time_map`). 변형 후보는 **자기 시간이 큰 함수 하나**로 좁힌다
  — 거시 합계가 아니라 그 함수의 몫이 상한이다(구조우선 「순서」 1).
- 캐시 미스: `valgrind --tool=cachegrind --cache-sim=yes` 를 SA csql(작은 데이터)에 붙여 `cg_annotate` 로 그 함수의 D1·LL miss 를 본다
  (서버는 느려서 SA 로). 행렬·구조체 접근 패턴(AoS→SoA 후보)의 근거가 된다.
- 파이프라인: `llvm-mca` 는 아직 없다(LLVM 미설치) — 설치되면 그 함수의 핫 루프 어셈블리(`objdump -d`)를 넣어 처리량·병목 포트를 본다.

## 2. 변형 — LLM 이 쓴다
- **원래 함수는 그대로 두고** 변형을 같은 시그니처로 쓴다(바뀐 엔진 커밋의 그 함수가 변형이 된다). 한 변형 = 한 함수.
- 변형 종류를 plan `changes[].variant.kind` 에 적는다: `simd`·`soa`·`loop`(언롤·융합)·`branchless`·`table` 등.
- 바뀐 것이 '같은 계산을 더 빠르게' 가 아니라 새 알고리즘·자료구조·동작 변경이면 동치 증명 대상이 아니다 → `variant_exempt` 에 이유와
  대신 볼 것(미시 벤치 출력 대조·A/B·TC)을 적는다.

## 3. 동치 증명 — CBMC
도구: `python3 tools/equiv/cbmc_equiv.py run --case <dir>` / `check --case <dir>`(게이트가 부른다). 템플릿 `tools/equiv/template/`.

케이스 디렉터리 만들기:
1. `case.json` — `file`·`function`(원래 이름)·`variant_function`(기본 같음)·`base`(원래 rev — develop 쪽)·`head`(변형 rev 또는 `WORKTREE`)·
   `sources`(cbmc 에 넘길 파일)·`unwind`(루프 상한)·`flags`(기본 `--bounds-check --pointer-check --signed-overflow-check`).
2. `orig.c`·`variant.c` — 각 rev 의 함수 정의를 **이름만** `<name>__orig`·`<name>__variant` 로 바꿔 그대로 옮긴다. 도구가 그 rev 의 소스와
   (주석·공백을 빼고) 글자 대조해, 다르면 증명하지 않는다 — 손으로 고친 '원래 함수' 로 증명하는 일을 막는다.
3. `stubs.h` — 두 함수가 쓰는 타입·매크로·도우미를 **최소로** 옮기거나 흉내 낸다(서버 구조체 전체를 들이지 않는다). 도우미가 순수 함수면
   그대로 옮기고, 부작용·서버 자원이면 nondet 를 돌려주는 stub 으로 둔다 — 그 가정은 `case.json` 의 `assumptions` 에 한 줄씩 적는다.
4. `harness.c` — `main` 에서 입력을 `nondet_*()` 로 만들고(필요하면 `__CPROVER_assume` 로 함수의 전제 — 길이 상한·NULL 아님), 두 함수에
   **같은 입력의 복사본**을 넣은 뒤 반환값과 출력(버퍼·구조체 필드)이 같다고 `assert` 한다. 부동소수는 비트 같음(`memcmp`)으로 — SIMD 의
   재결합이 결과를 바꾸면 그것이 반례다.

판정:
- `--unwinding-assertions` 는 도구가 늘 붙인다 — 상한 안에서만 증명된 것이 아니라 상한이 모든 경로를 덮는다는 것까지. 상한을 넘는
  입력이 있는 함수는 전제(`__CPROVER_assume`)로 입력 크기를 묶고, 그 묶음을 PR 본문에 적는다(증명 범위).
- `SUCCESSFUL` → `proof.json`(cbmc 판·명령·두 함수 본문과 모델 파일의 sha256). `FAILED` → `cex.txt`(반례 trace)와 `cex_inputs.json`(main 의 입력 변수마다 마지막 값 — 도구가 한 줄로도 찍는다): 입력 대입을 읽어
  **변형 단계에 되돌린다**(LLM 이 그 입력에서 왜 다른지 설명하고 변형을 고친다). 되돌림은 **3회**까지 — 넘으면 변형을 접고 사용자에게
  반례와 함께 보고한다(무한 재시도 금지). `ERROR` 는 모델(stub·파싱) 문제다 — 증명이 아니다.
- 게이트(implement_gate (5-1)): `rule_ids` 가 붙은 변경마다 `variant.equiv` 의 증명이 SUCCESSFUL 이고 지금 소스의 두 함수·모델 파일이
  증명 때와 같아야 통과. 아니면 `variant_exempt`. 증명 뒤 함수를 고쳤으면 다시 run.
- 증명이 통과해도 **미시 벤치**(구조우선 「측정 규약」)는 따로다 — 동치는 '같은 결과' 이지 '빨라짐' 이 아니다. 순서: 증명 → 벤치.

## 4. 한계 (보고에 적는다)
- CUBRID `.c` 는 C++17 로 컴파일되지만 CBMC 의 C++ 지원은 제한적이다 — 증명 대상은 **C 로 옮길 수 있는 함수**(판정·커널·변환)다.
  참조·템플릿·예외가 든 함수는 `variant_exempt`.
- 모델은 stub 위의 증명이다 — stub 의 가정(`assumptions`)이 틀리면 증명도 그 범위까지다.
- SIMD intrinsics(`_mm512_*`)는 CBMC 가 모른다 — 스칼라 의미로 옮긴 참조 구현을 stub 으로 두거나(그 대응을 `assumptions` 에),
  IR 수준 검증(Alive2, 다음 단계)으로 넘긴다.

## 설치 — 사람이 한다(외부 코드, TLA+ 와 같은 결정)
Rocky Linux 8 에는 공식 패키지가 없어 소스에서 굽는다(cmake·flex·bison·g++ 8 필요 — 세 컨테이너에 있다). 빌드 중 minisat 를 받으므로 망 연결이 필요하다. GCC 8 은 `std::filesystem` 에 `-lstdc++fs` 를 따로 링크해야 한다(없으면 `file_converter` 링크가 `path::_M_split_cmpts` undefined 로 실패 — 2026-11-20 .50, CBMC 6.11.0). 명령은 한 줄씩 실행한다(붙여 넣은 줄이 섞이면 앞이 실패해도 뒤가 돈다).
```bash
cd ~/tools && git clone --depth 1 --branch "$(git ls-remote --tags --refs https://github.com/diffblue/cbmc.git 'cbmc-6.*' | awk -F/ '{print $3}' | sort -V | tail -1)" https://github.com/diffblue/cbmc.git cbmc-src
cd cbmc-src && cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DWITH_JBMC=OFF -DCMAKE_CXX_STANDARD_LIBRARIES=-lstdc++fs && cmake --build build -j16 --target cbmc goto-cc goto-instrument
mkdir -p ~/tools/cbmc/bin && cp build/bin/cbmc build/bin/goto-cc build/bin/goto-instrument ~/tools/cbmc/bin/ && ~/tools/cbmc/bin/cbmc --version
```
확인: `python3 tools/equiv/cbmc_equiv.py run --case tools/equiv/template/example` 이 `SUCCESSFUL`. Alive2(LLVM·z3 를 소스에서 빌드, 수 GB)는 다음 단계.

확인(2026-11-20 .50, CBMC 6.11.0): 예제 `SUCCESSFUL`; 일부러 틀린 변형(끝 NUL 검사에서 마지막 바이트를 건너뜀)은 `FAILED`, 반례 `na=1, nb=4, b[3]=1`(원래 FALSE, 변형 TRUE) — 버그 자리를 바로 가리켰다.
