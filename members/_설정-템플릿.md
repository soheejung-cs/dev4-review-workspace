# 새 팀원 설정 — 이 파일을 복사해 `members/<이름>/README.md` 로 채운 뒤 첫 커밋을 한다

두 리포(`dev4-review-workspace`, `dev4-ai-source`)에 무엇을 넣든 **누가 썼는지**가 남아야 한다. 아래 셋을 먼저 맞춘다.

## 1. 나는 누구인가 (표를 채운다)
| 항목 | 값 |
|---|---|
| 이름(한글) | |
| GitHub 로그인 | |
| JIRA 아이디 (`jira.cubrid.org`, `name` 필드) | |
| 이메일 (커밋 저자용) | |
| 쓰는 컨테이너 / 머신 (있으면 IP 끝자리·hostname) | |
| 주 담당 영역 (`src/…` 디렉터리 또는 [A]~[I]) | |

채운 뒤 `members/README.md` 의 명단 표에 **한 줄 추가**하고, `tools/roster.json` 에도 같은 값을 넣는다(현황 생성기가 읽는다).

## 2. git 저자 설정 — 두 리포 각각에서 (전역 설정을 바꾸지 않는다)
```bash
for r in ~/dev/docs/dev4-review-workspace ~/dev/docs/dev4-ai-source; do
  git -C $r config user.name  "<이름(한글)>"
  git -C $r config user.email "<이메일>"
done
```
Claude Code 세션이 대신 커밋할 때도 **저자는 사람**이다 — 세션은 커밋 메시지 끝의 `Co-Authored-By:` 로만 남는다.
`git log --format='%an' -1` 이 내 이름이 아니면 커밋하지 않는다.

## 3. 기록 서명
- 소스 사실(dev4-ai-source): 파일 `staging/<이름>-<이슈명>.md`, 모듈 §2·§3 로 옮길 때 항목 끝에 `— 이름(.컨테이너) YYYY-MM-DD`.
- 리뷰 산출물(dev4-review-workspace): `reviews/` 나 스킬 예시에 넣을 때 파일 머리에 `작성: 이름 · 날짜 · 대상 PR`.
- 규약을 고칠 때(skills/*/SKILL.md): 바꾼 줄에 `(이름, 지시 날짜)`.
