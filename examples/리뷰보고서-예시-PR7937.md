> **TL;DR** (Non-blocking): 복합 FK 조인의 독립곱을 `1 / N(parent)` 바닥으로 바꾼 방향은 PG 의 `get_foreign_key_join_selectivity()` 와 같고, 바닥을 "이 단계에서 처음 연결될 때 한 번", term 이 아니라 equivalence class 로 찾는 설계는 `qo_check_skip_term()` 의 term 치환을 정확히 피한다. 남는 것은 (1) FK 컬럼이 nullable 로 선언되기만 해도 바닥을 통째로 포기하는 정책이 실제 스키마에서 적용 범위를 크게 줄인다는 점, (2) 검증이 TPC-H 하나라는 점. 둘 다 머지를 막을 사안은 아니다.

## Summary

- **변경 요약**: 플래닝 전 복합 PK 를 참조하는 FK 제약을 `env->fk_join_info` 에 등록하고, join 탐색의 각 단계에서 그 제약의 모든 컬럼 term 이 처음 갖춰질 때 개별 selectivity 곱을 빼고 `1 / N(pk_node)` 를 한 번 곱한다.
- **주요 이슈**: nullable FK 컬럼 = 바닥 포기(`qo_match_fk_prefix`) -- `(1 - null_frequency)` 보정으로 대체 가능.
- **확인 필요 사항**: TPC-H 외 워크로드(복합 FK 없는 JOB 등)에서 무변화인지, TC PR 두 개가 비어 있음, Q9 wall-time 회귀 후속 이슈.

## Findings

### [설계 리뷰]

영역 판정: **[B] SQL 컴파일(옵티마이저, 클라이언트측)** -- `query_graph.c`(제약 발견) + `query_planner.c`(join 단계 selectivity). 흔드는 불변조건 없음. 서버 변경 없음.

1. **PG 패리티**: FK 제약 하나 = 바닥 하나, 바닥은 `1 / N(parent 기본 카디널리티)`, 처음 연결되는 단계에만 적용 -- PG 와 같은 모형이다. pk_node 가 자체 필터로 줄어 있어도 `head.card × tail.card × 1/N(pk)` 가 되어 "부모 중 필터를 통과한 비율만큼의 자식 행"으로 맞게 떨어진다(검산: `|L| × |P_f| / |P|`).
2. **term 이 아니라 eqclass 로 찾는 이유가 코드에 적혀 있다** -- `qo_check_skip_term()` 이 리터럴 edge 를 지우고 다른 노드쌍의 등가 term 을 남기는 경우를 정확히 겨눈 설계다. fk_node 에 닿는 term 은 segment 동일성까지 요구해 서로 다른 FK 제약이 한 eqclass 로 합쳐지는 경우를 가른다. 채택.
3. **nullable FK 정책 (Oracle 스펙 대조)** -- Oracle SQL Reference 10g §8 constraint, 8-14: "To satisfy a composite foreign key constraint, the composite foreign key must refer to a composite unique key or a composite primary key in the parent table or view, **or the value of at least one of the columns of the foreign key must be null**." 즉 어느 한 컬럼이라도 NULL 인 자식 행은 부모가 없다 -- 바닥의 전제("자식 행마다 부모 정확히 하나")가 깨지는 것은 **그 행들만**이다. PR 은 컬럼이 nullable 로 *선언*되기만 하면 제약 전체를 등록하지 않는다(`qo_match_fk_prefix`, `QO_SEG_IS_NOT_NULL` 검사). 실제 null_frequency 가 0 인 흔한 스키마(FK 컬럼을 NOT NULL 로 선언하지 않는 관행)에서 이 수정이 전혀 발동하지 않는다. 대안: 바닥을 `(1 - nf) / N(pk)` 로 두고 `nf` 는 FK 컬럼들의 null_frequency 최대값(`_db_histogram.null_frequency`, 이미 수집됨)으로 잡는다 -- 전제가 깨지는 행의 비율만큼만 깎으므로 스펙에 정확히 대응한다. 비용 모델의 다른 곳(조인 선택도의 `(1-nf)` 이중 곱 규약)과도 같은 어휘다.
4. **이 책이 답하지 않는 것**: Oracle 의 FK 기반 카디널리티 추정 방식은 SQL Reference 범위 밖(Performance Tuning Guide) -- 매뉴얼 미확인으로 남긴다.
5. **AC2 회귀(Q9 +25%)를 이 PR 밖으로 둔 판단**에 동의한다 -- 카디널리티는 맞아졌고 틀린 것은 `qo_hjoin_cost()` 의 spill penalty 라는 분리 증명(두 플랜의 카디널리티 동일, penalty 비활성화 실험)이 본문에 있다. 단 후속 이슈 번호가 없다.
