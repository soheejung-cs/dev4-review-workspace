## 3. 확인했지만 결함 아님
- **미실행 값을 복제할 가능성**: 없다. `XASL_LINK_TO_REGU_VARIABLE` 부질의는 aptr 사전 실행 루프(`query_executor.c:14312`)에서 건너뛰지만, 그 뒤 16689-16710 의 precomp 루프가 `precomp_owner_regu` 가 있는 것만 `fetch_peek_dbval` 로 실행한다. 이 루프는 `#if SERVER_MODE` 밖이고 gather 모드 조건이 없다. INSERT … SELECT(Case 5)의 SELECT 와 lazy 로 실행되는 부질의 블록도 `qexec_execute_mainblock` 으로 들어오므로 같은 경로를 탄다.
- **`m_xasl` 이 원본인가**: 매니저가 받는 `xasl` 은 세 모드 공통이고, `m_uses_xasl_clone` 은 워커 클론 여부일 뿐이다. 중첩 병렬(자식 스레드에서 매니저 open)이면 `m_xasl` 은 이미 주입된 클론이라 그 값을 그대로 복제한다 — 일관.
- **누수**: `capture_precomp_vals` 는 `pr_clone_value` 로 넣고 `~pre_execution_info` 가 전부 `pr_clear_value`. `pre_execution_info` 는 `manager` 멤버라 `manager` 와 함께 소멸하고, `reset ()` 은 이 멤버를 건드리지 않는다.
- **파티션(Case 7)**: `reset () → open ()` 이 `m_task_started = false` 로 되돌려 `next ()` 가 다시 capture 하지만 `find` 뒤 `emplace` 라 첫 패스 값이 남는다. 직렬도 `status == XASL_SUCCESS` 로 한 번만 실행하므로 같다.
- **인덱스/리스트 스캔 TC 필요 여부**: `XASL_SNAPSHOT` 은 `HEAP` 에만 인스턴스화된다(`px_scan.cpp:2223`, `px_scan_task.cpp:1062`). TC 가 힙만 다루는 것이 맞다.
- **본문의 "기본값 256"**: `system_parameter.c:5181` 확인.
- **새 주석 문구**: "a worker that finds no value re-executes the subquery" 는 `px_scan_task.cpp:123-127`(`map_val == nullptr → continue`) 과 일치.
