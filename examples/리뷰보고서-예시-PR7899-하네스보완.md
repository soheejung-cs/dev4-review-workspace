## 새 지적

### [설계 리뷰]
- `btree.c:15038` — `xbtree_compact_overflow()` 의 리프 순회는 현재 리프 WRITE 를 든 채 다음 리프를 WRITE 로 잡는다(`:15038`, `:15047`). 오름차순 스캔은 READ-READ 커플링이라 문제가 없지만, 리프 병합(vacuum·delete 의 `btree_merge_node` 계열)이 이웃 리프를 **무조건** 래치로 잡는 순서가 있다면 "컴팩션: L 보유·L+1 대기 / 병합: L+1 보유·L 대기" 역전이 성립한다. 이웃 fix 가 CONDITIONAL(실패 시 병합 포기)인지 확인 요청. 팩 밖 코드라 단정하지 않는다. **왜 문제인가**: 페이지 래치에는 데드락 감지기가 없다 — 락 순서 역전은 감지기가 한쪽을 깨우지만 래치 역전은 두 스레드가 영원히 `pgbuf_fix` 안에서 잠들고, 그 리프에 닿는 DML·스캔·(SCH_S 때문에) DDL 까지 줄줄이 걸린다. 발생 확률이 낮아도 회복 불가 등급.

### [코드 리뷰]
