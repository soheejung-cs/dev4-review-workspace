## 2. 영역 판정

이 변경은 **[B] SQL 컴파일 + [E] 서버 실행 + [C] 객체(변환 표)** 세 계층에 걸치고, **불변조건은 흔들지 않는다.**

- **INV-2(클라이언트 사이드 컴파일) — 흔들지 않는다.** `domain_rules.h:55-67` 이 스스로를 "행에서 적용하던 **서버** 규칙(`qdata_*`, `tp_value_compare_with_error`, `tp_infer_common_domain`, 집계·분석의 행 시점 해석)의 단일 거처"로 한정했다. 43곳에 흩어진 서버 규칙의 **통합**이지 클라이언트 격자의 이식이 아니다. 충돌 시 **클라이언트가 이긴다** — `pt_make_regu_hostvar` 가 expected domain 으로 캐스트하면 그게 플랜 도메인이고, 캐스트하지 않는 세 경우(expected domain 없음·ENUM·LIMIT 피연산자)만 `tp_Variable_domain` 으로 "서버가 정하라"를 넘긴다.
- **INV-3(3-way 빌드) — 지켜진다.** `domain_plan/resolve/rules.c` 는 cubrid·sa 만, `object_domain_convert.cpp` 는 셋 다. `domain_rules.h`·`domain_resolve.h` 가 `#error` 로 CS 를 명시 차단한다.
- **임계도** Tier-0 에서 일을 빼는 방향(행당 타입 재판정 → 로드/게이트 1회). Tier-2 가 Tier-0 자원을 쥐는 형태 없음.
- **흔드는 것은 13.2 공유 자원 계약의 문서화 수준이다.** B등급(read-mostly) 자원인 XASL 캐시 엔트리 위에 `DOMAIN_PLAN` 이, 프로세스 전역에 키 쌍 표가 새로 얹혔는데 **P2 3요소 계약(불변식·허용 동시성·완화 기법)이 코드에 없다**(X1-01·X1-06).
