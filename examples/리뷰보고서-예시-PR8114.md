## 0. 먼저 알아야 할 것

### 이 PR 이 무엇을 바꾸나
NL 조인 inner 의 memoize(CBRD-26345)는 "inner 가 바깥 행에서 읽는 값" 을 키로 삼아 inner 결과를 재생한다. develop 의 키 생성기(`key_maker`)는 inner 의 술어와 inner 에 붙은 상관 부질의(dptr)에서 찾은 **TYPE_CONSTANT regu 전부**를 키에 넣었다 — 거기에 **부질의 결과값**(regu->xasl == dptr)과 부질의 outptr 로 들어온 **집계 accumulator** 가 섞였다. 둘 다 memo 를 조회한 **뒤** inner 행마다 계산되므로, 저장 시점 키에는 그 행의 결과가, 조회 시점 키에는 마지막으로 읽은 행의 결과가 들어가 같은 조인 키의 두 번째 바깥 행부터 결과가 다른 inner 행은 재생되지 않았다(이슈 질의 82 ≠ 100). 또 재생된 행은 inner 의 dptr 를 초기화하지 않아 가장 안쪽 scan 에 붙는 select list 부질의가 직전 행의 값을 돌려줬다.

## 3. 확인했고 문제 없던 것
1. **level 0 키에서 뺀 것이 정확히 dptr 결과뿐인가** — `regu_var->xasl == dptr` 비교(223). 상위 노드 dptr 의 결과(바깥 행마다 상수)·aptr 결과는 그대로 키에 남는다. 맞다.
2. **부질의 안을 `CORRELATED` 로만 좁혀도 바깥 참조를 잃지 않나** — 플래그는 상관 분기에서 무조건(10264). 중첩 부질의가 중간 부질의 컬럼을 참조하면 플래그가 붙은 채 올라와 중간 단계의 vfetch_to 제외로 걸러진다(기존 메커니즘).
3. **키 범위에만 있는 상관 참조** — where_range 경유로 수집(§0 신뢰도 ⓑ). TC 가 없을 뿐(T1).
4. **재생 행의 dptr 초기화가 술어 전용 부질의를 다시 돌리지 않나** — `qexec_execute_dptr_list` 는 LINK 부질의를 실행하지 않고(3417-3419) status 만 초기화, 재실행은 fetch 시점(ⓒ). 본문 주장 그대로.
5. **ENDED 분기에 초기화가 없어도 되나** — 일반·SEMI 의 ENDED 는 행을 내보내지 않음(8576); ANTI 의 ENDED 는 anti_survive 로 가서 초기화(8565→8474). Greptile 1차 지적에 대한 작성자 반영(116bd0ace) 이 맞다.
6. **possible_check 가 거부하는 모양 밖에 상관 참조가 숨을 자리** — fptr/bptr·다중 spec·UNION(spec 없음)은 모든 level 에서 거부, 집계 인자·HAVING·rownum·orderby_num 은 방문. limit 는 상관 불가. 남는 건 TYPE_OID 상관 참조(기존에도 미수집) 정도.
7. **BUILDVALUE 의 HAVING 부질의** — 가장 안쪽 scan 의 dptr 에 붙고(xasl_generation.c:17721) scan_ptr 재귀가 그 dptr 를 방문한다. eptr_list 거부는 BUILDLIST(GROUP BY) 전용이라 맞다.
8. pr_refs: 참조 커밋·PR 정상. Greptile 2건은 모두 반영됨(ENDED 분기 이동, TC 는 TC 리포).
