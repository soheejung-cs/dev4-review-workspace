> **원문**: Bilokon & Gunduz, *C++ design patterns for low-latency applications including high-frequency trading* (Imperial College London, 2023, SSRN 4565813)
> **코드 저장소**: github.com/0burak/imperial_hft
> **정리 목적**: 논문 전체를 한국어로 공부용 재구성. 각 기법마다 "개념 → 왜 빨라지나 → 측정 결과 → 주의점" 순서로 정리. 수치는 전부 논문의 Google Benchmark / perf 실측값.

## 0. 이 논문이 하려는 것 (한 줄 요약)

HFT 업계는 폐쇄적이라 저지연 최적화 노하우가 공개 자료로 거의 없음. 그래서 저자들이 (1) 저지연 기법 13개를 직접 벤치마크한 저장소를 만들고, (2) 그 기법들을 실제 페어 트레이딩 전략에 적용해 **87% 지연 감소**를 달성하고, (3) LMAX Disruptor를 C++로 구현해 일반 큐 대비 성능을 검증한 논문.

## Part 1. 배경 지식

### 1.1 HFT란

SEC가 정의한 HFT의 5가지 요소:

1. 초고속 컴퓨팅 인프라 사용
2. 거래소 데이터센터와의 **코로케이션**(colocation, 물리적 근접 배치)
3. 포지션 진입~청산까지의 시간이 극도로 짧음
4. 대량 주문 제출 후 빠른 취소를 반복
5. 장 마감 시 포지션을 거의 중립(무헤지 노출 최소)으로 정리

시스템은 5개 컴포넌트로 구성: **데이터 피드**(시세 수신) → **트레이딩 전략**(신호 생성) → **OMS**(주문 제출/라우팅/추적) → **리스크 관리** → **실행 인프라**(네트워킹). 이 논문의 초점은 전략과 OMS.

전략 유형: 통계적 차익거래(statistical arbitrage), 모멘텀, 페어 트레이딩, 유동성 탐지, 뉴스 기반 트레이딩 등. 2016년 기준 HFT가 미국 주식 거래량의 10~40%를 차지한다는 추정이 있음.

**FPGA 참고**: 대형 HFT사는 FPGA로 특정 알고리즘을 일반 CPU 대비 최대 1000배까지 가속. 특징은 재프로그래밍 가능성, 용량, 병렬성, 결정성(determinism). 단, 이 논문은 하드웨어가 아니라 **소프트웨어/코드 레벨 최적화**만 다룸.

### 1.2 왜 C++인가

- 컴파일 언어 + 하드웨어 근접 제어 + "zero-overhead" 철학. GC가 없어서 메모리 사용이 결정적(deterministic).
- 런타임 비용을 **컴파일 타임으로 이동**시키는 수단이 풍부함: 템플릿(CRTP 포함), inline, constexpr.
- **Java도 불가능하진 않음**: LMAX Disruptor 원본이 Java고, Nasdaq OMX도 GC를 꺼둔 Java로 운영. 링 버퍼를 사전 할당해 GC 개입을 원천 차단하는 방식. GC 튜닝이 잘 맞으면 특정 상황에서 C++보다 빠른 사례도 보고됨.
- **Rust**: GC 대신 ownership/borrowing으로 메모리 관리. C++과 Java의 중간 지점. 떠오르는 대안이지만 논문은 C++로 진행.
- 실무 팁: 컴파일러 버전, 아키텍처, 빌드 플래그가 지연에 큰 영향을 주므로 **Compiler Explorer(godbolt)** 로 생성된 어셈블리를 직접 확인하는 습관이 중요.

### 1.3 측정 도구와 캐시 기초

- **Google Benchmark**: 코드 조각을 통계적으로 반복 측정. CPU-bound 측정에 강함. 단, 네트워크 지연·코로케이션·하드웨어 타임스탬핑 같은 HFT 특유 요소는 못 봄 → 다른 도구와 병행 필요.
- **perf (Linux)**: 캐시 미스 등 하드웨어 카운터 분석에 사용.
- **벤치마크는 환경 의존적**: 한 발표 사례에서 `clock_gettime`이 벤치마크 사이트에선 Intel TSC보다 85배 느리게 나왔는데, 실제 운영 서버에서 재측정하니 2배 차이에 불과했음. → *내 환경에서 직접 재라*가 교훈.
- 캐시 기초 수치 감각 (논문 인용 자료 기준): L1 참조 ≈ 0.5ns, 분기 예측 실패 ≈ 5ns, L2 ≈ 7ns, 뮤텍스 lock/unlock ≈ 25ns, 메인 메모리 ≈ 100ns. **L1과 메인 메모리는 200배 차이** — 저지연 최적화의 대부분이 결국 캐시 이야기인 이유.

> ⚠️ 개선율은 각 기법의 마이크로벤치마크 결과라 워크로드가 서로 다름. "cache warming이 inlining보다 4배 좋다"처럼 가로 비교하면 안 되고, 각 기법이 자기 시나리오에서 얼마나 먹히는지의 감각으로만 볼 것.

---

### 2.1 Cache Warming — 개선율 ~90%

**개념**: 핫 패스(hot path)가 실행되기 *전에* 필요한 데이터/명령어를 미리 캐시에 올려두는 것.

**HFT 맥락**: 거래 신호에 반응하는 실행 경로가 핫 패스인데, 신호는 가끔만 오지만 왔을 때는 극도로 빨라야 함. 그래서 **매 틱마다 실행 엔진 코드를 항상 실행하되, 실제 주문은 신호가 있을 때만 내보내는** 구조로 캐시를 계속 "따뜻하게" 유지. 대기 시간을 캐시 예열에 쓰는 발상.

**벤치마크 설계**: 큰 배열을 랜덤 순서로 접근(BM_CacheCold) vs 순차 접근으로 예열 후 접근(BM_CacheWarm). `benchmark::DoNotOptimize`로 컴파일러의 제거 최적화 방지.

**결과**:

| 항목 | Cold | Warm |
|---|---|---|
| 실행시간 | 267,685,006 ns | 25,635,035 ns |
| 명령어 수 | 4.93B | 12.01B |
| 캐시 참조 | 146M | 61M |
| 캐시 미스율 | 73.96% | 71.56% |

**흥미로운 포인트**: 미스*율*은 거의 같은데 총 캐시 참조 *횟수* 자체가 줄면서 빨라짐. 미스율만 보면 놓치는 그림이 있다는 것. 순차 접근이 spatial locality를 활용한 결과.

**주의점**: 접근 패턴이 예측 가능할 때만 유효.

---

### 2.2 Compile-time Dispatch — ~26%

**개념**: 어떤 함수가 호출될지를 런타임(가상 함수/vtable)이 아니라 **컴파일 타임**(템플릿 특수화, 오버로딩, CRTP)에 결정.

**결과**: 런타임 디스패치(가상 함수) 2.60ns / 2.15ns → 컴파일타임 디스패치 1.92ns. vtable 조회 + 간접 호출 오버헤드가 사라지고, 컴파일러가 인라인 등 추가 최적화를 할 수 있게 됨.

**트레이드오프**: 런타임 유연성(다형성)을 포기하는 대신 속도를 얻음.

---

### 2.3 Constexpr — ~90.9%

**개념**: `constexpr`로 표시된 계산을 컴파일 타임에 평가 → 런타임에는 상수만 남음.

```cpp
constexpr int factorial(int n) {
    return (n <= 1) ? 1 : n * factorial(n - 1);
}
// factorial(10)이 컴파일 타임에 3628800으로 접힘(constant folding)
```

**결과**: factorial(10) 계산이 constexpr 0.245ns vs 런타임 2.69ns (약 90.88% 개선).

**중요한 해석 주의**: 이건 "constexpr을 붙이면 코드가 빨라진다"가 아니라 **계산 자체가 런타임에서 사라진 것**. 목적은 런타임 속도 향상이 아니라 계산의 컴파일 타임 이전(shift). 또한 컴파일러는 constexpr이 없어도 상수 접기를 할 수 있어서, 항상 이만큼의 차이가 나는 건 아님.

---

### 2.4 Inlining — ~20.5%

**개념**: 함수 호출을 함수 본문으로 치환해 호출 오버헤드(인자 전달, 스택 프레임, call/ret)를 제거. GCC의 `__attribute__((always_inline))`은 최적화 레벨과 무관하게 강제 인라인.

**결과**: 인라인 1.90ns vs 비인라인 2.39ns.

**주의점**: 남용하면 바이너리가 커져서 **명령어 캐시(i-cache) 효율이 오히려 나빠질 수 있음**. 작고 자주 호출되는 함수에 선별 적용.

---

### 2.5 Loop Unrolling — ~72%

**개념**: 루프 본문을 여러 번 복제해 반복 횟수를 줄임 → 루프 제어(카운터 증가, 비교, 조건 점프) 오버헤드 감소. 속도 ↔ 코드 크기의 트레이드오프.

```cpp
// 언롤 전                          // 4배 언롤 후
for (i = 0; i < n; ++i)            for (i = 0; i < n; i += 4)
    result += i;                       result += i + (i+1) + (i+2) + (i+3);
```

**결과**: 1000회 합산 루프 기준 4539ns → 1260ns.

**주의점**: 과도한 언롤은 바이너리 팽창 → i-cache 미스 증가, 수확 체감. 메모리 접근이 병목인 루프는 언롤해도 별 이득 없음. 프로파일링 필수.

---

### 2.6 Short-circuiting — ~50%

**개념**: `A || B`에서 A가 참이면 B를 평가하지 않는 논리 연산 단축. 비싼 조건 검사를 뒤로 배치하면 대부분의 경우 실행 자체를 회피.

**결과**: 반복 횟수 8 ~ 8192 전 구간에서 일관되게 약 50% 개선 (예: 8192회 기준 12.4초 → 5.84초 수준의 스케일).

**실무 감각**: 조건 순서 배치가 곧 성능. 싸고 자주 걸러지는 조건을 앞에.

---

### 2.7 Slowpath Removal — ~12%

**개념**: 자주 실행되는 핫 패스와 드물게 실행되는 슬로우 패스(에러 처리, 로깅 등)를 분리. 슬로우 패스를 **non-inline 함수 하나**로 몰아넣어 핫 패스의 i-cache 오염을 방지.

```cpp
// 나쁜 설계: 에러 검사가 핫 패스에 줄줄이 인라인됨
if (checkErrA()) handleA();
else if (checkErrB()) handleB();
else sendOrderToExchange();

// 좋은 설계: 에러는 플래그 하나로 모으고, 처리 코드는 밖으로
if (!errorFlags) sendOrderToExchange();   // hot
else HandleError(errorFlags);             // cold, non-inline
```

**결과**: 핫 패스 90% / 슬로우 패스 10% 비율 시나리오에서 28,074ns → 24,755ns.

---

### 2.8 Branch Reduction — ~36%

**개념**: 분기 예측 실패(misprediction)는 파이프라인 스톨을 유발. 조건 분기 자체를 줄이면 예측 실패 기회도 줄어듦. 여러 에러 검사를 정수 플래그 하나로 합쳐 **분기 1개**로 축소. `__builtin_expect` 같은 컴파일 타임 힌트도 같은 계열.

**결과**: 관행적 if-else 체인 7.35ns → 플래그 방식 4.68ns.

**Slowpath removal과의 관계**: 둘이 세트로 자주 같이 씀. slowpath removal은 i-cache 관점, branch reduction은 분기 예측 관점의 같은 구조 개선.

---

### 2.9 Prefetching — ~23.5%

**개념**: 데이터가 필요해지기 전에 `__builtin_prefetch` 등으로 미리 캐시로 로드. 접근 패턴이 예측 가능한 경우(배열 순회, 행렬 처리)에 유효.

**결과**: 대형 벡터 합산에서 8,235,924ns → 6,301,400ns.

**주의점**: 효과는 CPU 아키텍처, 데이터 크기, 접근 패턴 예측 가능성에 크게 좌우됨. Cache warming이 "실행 전 예열"이라면 prefetch는 "실행 중 앞서 당겨오기".

---

### 2.10 Signed vs Unsigned 비교 — ~12.15%

**개념**: 루프 변수 등에서 signed와 unsigned의 오버플로우 의미론 차이가 생성 어셈블리를 바꿈.

**핵심 메커니즘** (이 논문에서 제일 재밌는 어셈블리 분석):
- **unsigned 오버플로우는 정의된 동작**(wrap-around) → 컴파일러가 `i + 10`이 랩어라운드하는 경우까지 정확히 처리해야 해서 `lea/cmp/sbb/and` 같은 추가 명령이 붙음.
- **signed 오버플로우는 UB** → 컴파일러가 "오버플로우는 없다"고 가정하고 루프 전체를 상수 10으로 접어버림 (`mov eax, 10; ret`).

**결과**: signed 0.282ns vs unsigned 0.321ns.

**교훈**: "UB라서 컴파일러가 더 공격적으로 최적화할 수 있다"는 C++의 유명한 역설 사례. 인덱스/루프 변수는 signed(`int`, `ptrdiff_t`)가 최적화에 유리한 경우가 있음.

---

### 2.11 Float/Double 혼용 회피 — ~52%

**개념**: `float`와 `double`이 한 수식에 섞이면 암시적 승격(float→double)과 강등(double→float)이 발생. 루프 안에서 수백만 번 반복되면 무시 못 할 비용.

```cpp
float a, b;
a = b * 1.23;    // 1.23은 double 리터럴 → 변환 2회 발생
a = b * 1.23f;   // float 리터럴 → 변환 없음
```

**결과**: 혼용 21.6ns vs float 통일 14.2ns.

**주의점**: double→float 강등은 정밀도 손실 이슈도 있음. 타입을 통일하되 필요한 정밀도를 먼저 결정할 것.

---

### 2.12 SIMD — ~49%

**개념**: Single Instruction Multiple Data. 명령 하나로 여러 데이터를 동시 처리. 논문 예제는 SSE2(128-bit 레지스터, packed float 병렬 처리).

**결과**: 배열 덧셈에서 순차 21,447ns → SIMD 10,929ns.

**적용처**: 대량 배열/행렬 연산, 벡터화 가능한 수치 계산. (Part 3에서 AVX2로 실전 적용.)

---

### 2.13 Lock-Free Programming — ~63%

**개념**: 뮤텍스 같은 상호 배제 없이 **원자적 연산**(CAS: Compare-And-Swap, LL/SC)만으로 동시성 제어. 데드락/락 경합/컨텍스트 스위치를 회피.

**CAS 동작**: (메모리 위치, 기대값, 새 값)을 받아, 현재 값 == 기대값일 때만 원자적으로 교체. 실패하면 재시도 루프.

**결과**: 멀티스레드 카운터 증가 10,000회 — `std::atomic` 65,369ns vs mutex 175,904ns.

**주의점**:
- 락이 비싼 이유: 경합 시 중재가 컨텍스트 스위치로 이뤄지고, 그 과정에서 캐시 무효화/플러시/재적재 비용이 발생.
- CAS도 공짜가 아님: 파이프라인 잠금 + 메모리 배리어 필요.
- lock-free 코드는 설계·디버깅 난도가 훨씬 높고 실패 모드가 비직관적. **필요한 곳에만 신중히**.

### 2.14 Kernel Bypass (벤치마크 없음, 개념 소개)

**개념**: 일반적으로 네트워크 I/O는 커널을 경유(패킷 → NIC → 커널 → 유저 공간 복사)하며 컨텍스트 스위치와 메모리 복사 비용이 큼. 커널 바이패스는 유저 애플리케이션이 **NIC와 직접 통신**해 이 경로를 제거.

**대표 기술**: Solarflare OpenOnload, Mellanox VMA, Intel DPDK. DPDK는 전통 리눅스 네트워킹 스택 대비 **지연 7배 감소** 보고 사례가 있음.

**주의점**: 전용 NIC/드라이버 필요. 커널의 보안·격리 메커니즘을 우회하므로 시스템 안정성/보안 리스크 관리 필요.

## Part 3. 실전 적용: 통계적 차익거래 페어 트레이딩

### 3.1 전략 개념

- **페어 트레이딩** = 상대가치 차익거래. 역사적으로 가격이 같이 움직이는 자산 쌍을 찾아, 둘의 가격 차이(**스프레드**)가 평균에서 벗어나면 되돌아온다(**mean reversion**)에 베팅.
- 스프레드 확대 시: 고평가된 쪽 공매도 + 저평가된 쪽 매수 → 시장이 오르든 내리든 스프레드 수렴이면 수익. 그래서 **시장 중립**(market-neutral).
- 기원: 1980년대 후반 Morgan Stanley의 퀀트 그룹(Nunzio Tartaglia).
- 페어 선정: 같은 산업/섹터 위주(개별 기업 리스크 상쇄), 공적분 검정·상관 분석으로 확인.

### 3.2 공적분(Cointegration) — 이 전략의 수학적 근거

- 두 시계열이 각각은 **비정상**(non-stationary, 통계적 성질이 시간에 따라 변함)이어도, 그 **선형 결합 Z = Y − γX가 정상(stationary)** 이면 공적분 관계. → 장기 균형에서의 이탈이 일시적이고 평균 회귀한다는 뜻.
- 단순 상관과의 차이: 상관은 "같이 움직이는 정도", 공적분은 "장기 균형 관계의 존재". 페어 트레이딩엔 후자가 본질.
- **Engle-Granger 2단계 검정**: ① 한 시계열을 다른 시계열에 OLS 회귀 → 잔차 획득. ② 잔차에 ADF(Augmented Dickey-Fuller) 단위근 검정 → 잔차가 정상이면 공적분.
- 논문 사례: **Goldman Sachs(GS) vs Morgan Stanley(MS)** 5년 일간 종가. p-value ≈ 0.0149, t ≈ −3.77 → 유의수준 0.05에서 "공적분 없음" 귀무가설 기각. 
- 통계는 증거일 뿐 증명이 아님 → 그래서 "순수 차익거래"가 아니라 "**통계적** 차익거래". 3개 이상 시계열이면 Johansen 검정이 더 강건.

### 3.3 매매 로직

1. 데이터: 수정종가(Adj Close — 배당·분할 반영이라 그냥 Close보다 정확).
2. 롤링 윈도우 N으로 스프레드의 평균 μ, 표준편차 σ 계산.
3. 현재 스프레드를 표준화 → **z-score = (X − μ) / σ**.
4. 시그널:
   - z > 1.0 → GS 고평가 → GS 숏 + MS 롱
   - z < −1.0 → GS 저평가 → GS 롱 + MS 숏
   - |z| < 0.8 → 평균 회귀 완료로 판단, 포지션 청산
   - 그 외 → 중립(무행동)
5. 백테스트 결과(참고용): $1,000,000 → $1,328,581, **Sharpe ratio 1.09** (Sharpe = (Rp − Rf)/σp, 위험조정수익 지표). 논문의 초점은 수익률이 아니라 지연이므로 참고만.

### 3.4 지연 최적화 적용 (Part 2 기법의 실전 조합)

| 적용 기법 | 내용 |
|---|---|
| **SIMD (AVX2) + loop unrolling** | 스프레드의 합·제곱합 계산을 256-bit 벡터 연산으로 4개씩 병렬 처리. 제약: 윈도우 크기가 4의 배수여야 함 |
| **고정 크기 배열 + 롤링 인덱스** | 동적 할당 제거. 가장 오래된 스프레드 값을 새 값으로 덮어쓰는 링 버퍼식 구조 |
| **Inlining** | 평균/표준편차 계산 함수 인라인 |

**결과** (baseline 평균 517,559ns, 각 10회 측정):

| 기법 | 지연(ns) | 개선율 |
|---|---|---|
| Inlining 단독 | 406,709 | 21.41% |
| SIMD + unrolling 단독 | 355,618 | 31.28% |
| 고정 배열 단독 | 266,146 | 48.58% |
| **전부 결합** | **65,580** | **87.33%** |

- 표준편차도 4,233ns → 400ns로 급감 → 빨라졌을 뿐 아니라 **지연이 일관적/예측 가능**해짐. HFT에선 평균 못지않게 tail latency 일관성이 중요.
- 통계 검정: 각 최적화에 대해 paired t-test 수행, t-statistic 이 매우 크고 p-value가 극도로 작음(결합 기준 p ≈ 3.17e-35) → 우연이 아님. 단 표본 10개는 적은 편이라는 한계 인정.

### 3.5 캐시 분석의 반전 포인트

| 버전 | 명령어 수 | 캐시 미스율 |
|---|---|---|
| 무최적화 | 6.01B | 16.0% |
| 고정 배열 | 8.27B | 19.1% |
| Inlining | 9.07B | 19.2% |
| SIMD | 8.35B | 16.8% |
| **결합 최적화** | **3.27B** | **33.9%** |

결합 버전은 **캐시 미스율이 2배인데도 가장 빠름** — 총 명령어 수가 절반 가까이 줄었기 때문. 개별 기법들은 오히려 명령어 수가 늘었는데도 빨라짐(실행 효율/메모리 접근 패턴 개선). → **단일 지표(미스율)만 보고 성능을 판단하면 안 된다**는 실증 사례.

### 3.6 왜 지연을 줄이면 돈이 되는가 (수익성 연결 고리)

- **상대 속도**: 가장 빠른 HFT 회사들이 일관되게 더 높은 Sharpe/수익 실현 (Baron et al.). 짧은 정보 우위 + 리스크 관리 두 경로.
- **Latency Arbitrage Opportunity (LAO)** 성립 조건 (Wah의 모델):
  1. **Crossed market**: 시장1의 bid > 시장2의 ask (사서 즉시 되팔면 차익)
  2. **NBBO 조건**: 해당 가격이 전국 최우선호가(National Best Bid/Offer) 이상으로 유리할 것
  3. **시간 생존성**: 가격 괴리가 존재하는 시간 창이 양수 — 보통 밀리초 단위라 빠른 자만 잡음
- **절대 속도의 정량 효과** (Ende et al., 독일 거래소 회귀분석): **지연 1% 증가 ↔ 불리한 호가창 변화에 노출될 확률 0.9% 증가**. 이 논문의 87.32% 지연 감소를 대입하면 불리한 호가창 변화 노출 약 **78.6% 감소**.

### 3.7 백테스트의 한계 (저자 스스로 인정)

- 백테스트는 가격을 미리 벡터에 로드해 둠 → 실거래의 네트워크 지연, 돌발 뉴스, 불규칙 패턴을 반영 못 함.
- 윈도우 크기 4의 배수 제약은 전략 유연성을 제한.
- AVX2 의존 → 해당 명령어셋 없는 하드웨어에선 이득 없음.

## Part 4. LMAX Disruptor — 저지연 스레드 간 통신

### 4.1 기존 방식의 문제

- **락 기반 큐**: 경합 시 중재 = 컨텍스트 스위치. 이때 이전 스레드의 캐시가 무효화되고, 새 스레드는 캐시를 다시 채워야 함. 락 자체 비용(~25ns)보다 이 부수 효과가 더 큼.
- **CAS 기반**: 락보단 낫지만 파이프라인 잠금 + 메모리 배리어 비용, 그리고 복잡한 시스템을 CAS만으로 조율하기 어려움.
- **Bounded queue**: head/tail/size 변수에 쓰기 경합 집중 → 캐시 코히런시 문제.

### 4.2 Disruptor의 해법

- 핵심 = **사전 할당된 링 버퍼**(고정 크기 원형 배열) + **시퀀스 번호** 기반 조율.
- 단일 생산자면 락도 CAS도 불필요 — **메모리 배리어만으로** 가시성 보장. (다중 생산자일 때만 슬롯 클레임에 CAS.)
- **배칭 효과**: 소비자가 커서를 확인했을 때 여러 칸 전진해 있으면, 그 지점까지의 이벤트를 동시성 메커니즘 개입 없이 한 번에 몰아서 처리 → 버스트 상황에서 자연스럽게 따라잡음. 부하와 무관하게 일관된 지연 제공(메모리 포화 전까지).
- LMAX 자체 벤치마크 주장: 3단계 파이프라인에서 큐 대비 평균 지연 **3자릿수(1000배) 감소**, 처리량 약 8배.

### 4.3 구성 요소 (용어 정리)

| 구성 요소 | 역할 |
|---|---|
| **Ring Buffer** | 이벤트를 담는 사전 할당 원형 구조. 런타임 할당/GC 없음 |
| **Producer** | 슬롯 클레임 → 데이터 기록 → 시퀀스 갱신으로 공개 |
| **Sequencer** | 시퀀스 번호 발급/추적. 생산자-소비자 간 동기화 지점 |
| **Sequence Barrier** | 소비자가 안전하게 읽을 수 있는 시퀀스인지 판별 |
| **Event Processor (Consumer)** | 이벤트 소비. 여러 소비자를 의존성 그래프(파이프라인 단계)로 구성 가능 |
| **Event** | 전달 단위. HFT에선 OMS로 보낼 주문 객체 등 |
| **Wait Strategy** | 이벤트 없을 때 대기 방식. busy-spin(최저 지연, CPU 소모 큼) ↔ yield ↔ sleep(지연↑, CPU↓) 트레이드오프 |

### 4.4 C++ 구현 성능 (vs std::queue + mutex + condition_variable)

| 이벤트 수 | Queue (ns) | Disruptor (ns) | 개선 |
|---|---|---|---|
| 10 | 20,646 | 18,182 | 11.9% |
| 100 | 99,458 | 64,686 | 35.0% |
| 1,000 | 881,092 | 451,251 | 48.8% |
| 10,000 | 9,735,102 | 4,361,096 | 55.2% |
| 100,000 | 90,088,609 | 52,562,872 | 41.7% |
| 1,000,000 | 884,871,405 | 543,171,556 | 38.7% |

- **이벤트 수가 늘수록 격차 확대** — LMAX의 주장과 일치. 평균 약 38% 우위.
- 통계 검정 (이벤트 1000개, 20회): Queue 평균 931,255ns(σ=453,766) vs Disruptor 74,908ns(σ=53,600), t = 22.596, p ≈ 1.2e-23. 표준편차 격차에 주목 — Disruptor는 지연 분산 자체가 작음.
- 캐시: 소규모(10~100 이벤트)에선 Disruptor 미스율이 약간 높지만, 1,000개 이상부터 역전. 명령어 수도 더 적음(10 이벤트 기준 약 586K개 절약).

### 4.5 Disruptor 평가의 한계

- 속도만 측정 — 메모리 사용량, CPU 부하는 미평가 (busy-spin 계열은 CPU를 태워서 지연을 사는 구조라 이게 중요).
- Wait strategy는 yield 하나만 테스트. 전략별 지연/CPU 프로파일 비교는 향후 과제.

## 부록 A. DB 엔진 개발자 관점 메모 (개인 학습용 연결)

논문은 HFT 얘기지만 기법 자체는 범용 저지연 시스템 프로그래밍이라 DB 서버 엔진에 거의 그대로 대응됨:

- **Slowpath removal / branch reduction** ↔ 쿼리 실행기 내부 루프에서 에러 체크·희귀 케이스를 `unlikely` 경로로 분리하는 패턴. 실행기 한 row당 도는 코드에서 특히 효과적.
- **Cache warming / prefetching** ↔ 스캔 오퍼레이터의 페이지/튜플 프리페치, 버퍼 풀 예열.
- **SIMD** ↔ 벡터화 실행(columnar 집계, 필터). TPC-H 같은 분석 워크로드에서 분석계 엔진들이 빠른 핵심 이유 중 하나.
- **Lock-free / Disruptor** ↔ WAL 그룹 커밋, 로그 버퍼, 통계 수집 파이프라인처럼 생산자-소비자 구조가 있는 곳. "단일 생산자면 배리어만으로 충분"이라는 원칙은 로그 writer 설계와 직결.
- **Compile-time dispatch / inlining** ↔ 타입별 비교 함수, expression 평가처럼 가상 호출이 반복되는 지점의 특수화.
- **미스율 ≠ 성능** (3.5절) ↔ 옵티마이저/실행기 튜닝 때 perf 지표 하나만 보고 판단하지 말 것.

## 부록 B. 용어집 (빠른 복습용)

| 용어 | 뜻 |
|---|---|
| Hot path | 성능을 결정하는, 자주(또는 결정적 순간에) 실행되는 코드 경로 |
| Cache hit / miss | 요청 데이터가 캐시에 있음 / 없어서 하위 메모리에서 가져와야 함 |
| Spatial / temporal locality | 인접 데이터가 곧 쓰일 가능성 / 방금 쓴 데이터가 다시 쓰일 가능성 |
| Branch misprediction | CPU의 분기 예측 실패 → 파이프라인 비우기 페널티(~5ns) |
| i-cache | 명령어 캐시. 코드 크기가 커지면 오염됨 (inlining/unrolling의 부작용 지점) |
| CAS | Compare-And-Swap. lock-free의 기본 원자 연산 |
| Memory barrier | 메모리 연산 순서/가시성을 강제하는 명령 |
| Constant folding | 컴파일러가 상수 계산을 컴파일 타임에 미리 수행 |
| UB (Undefined Behavior) | 표준이 동작을 정의하지 않음 → 컴파일러가 "안 일어난다"고 가정하고 최적화 |
| Colocation | 거래소 데이터센터 안/옆에 서버를 두는 것 |
| Spread (페어 트레이딩) | 두 자산 가격의 차이 |
| Stationary(정상성) | 시계열의 통계적 성질이 시간 불변 |
| Cointegration(공적분) | 비정상 시계열들의 선형 결합이 정상인 관계 = 장기 균형 존재 |
| ADF test | 단위근(비정상성) 검정. 잔차 정상성 확인에 사용 |
| z-score | (값 − 평균)/표준편차. 표준화된 이탈 정도 |
| Sharpe ratio | (수익률 − 무위험수익률)/변동성. 위험조정수익 |
| NBBO | 미국 전 거래소 통합 최우선 매수/매도 호가 |
| Adverse selection | 정보 열위로 불리한 체결을 당하는 것. 느릴수록 노출 증가 |
| Kernel bypass | 커널을 우회해 유저 공간에서 NIC와 직접 I/O |
