## 0. 읽기 전에: 이 책의 성격 (솔직한 평가)

먼저 알고 읽어야 시간 낭비를 안 함. 이 책은 SSRN 논문과 성격이 완전히 다름:

- **서술이 장황하고 반복적.** 같은 얘기(속도가 중요하다, C++이 적합하다)가 챕터마다 되풀이됨. Reactive Publishing 계열의 자가출판 서적 특유의 스타일.
- **그럼에도 얻을 것**: HFT라는 도메인의 **전체 지도**. 시장 데이터 종류, 실행 알고리즘(VWAP/TWAP/Iceberg), 리스크 컨트롤 체계, 규제 지형, 배포 체크리스트 같은 "업계에서 뭘 신경 쓰는지"의 어휘와 목차는 잘 정리되어 있음.

**추천 활용법**: 이 정리본으로 도메인 지도를 잡고, 기술적 깊이(측정, 최적화의 실제 효과)는 논문 정리본으로 채우는 조합. 원서를 정독할 필요는 없음.

## Part 1. HFT 도메인 지도 (Ch.1)

### 1.1 트레이딩의 진화 경로

객장 호가(open outcry) → 전자 거래(1971 NASDAQ, 최초의 전자 증권시장; ECN으로 시간외 거래) → 알고리즘 트레이딩 → HFT. 전자화가 (1) 물리적 장벽 제거, (2) 접근 민주화, (3) 속도 경쟁의 판을 깔았고, HFT는 그 극단.

### 1.2 HFT의 3요소 삼각형

**속도**(초저지연 인프라) × **알고리즘**(실시간 데이터 기반 의사결정) × **인프라**(커스텀 서버, 코로케이션, 전용 광케이블). 셋은 상호의존적 — 어느 하나만 좋아선 무의미.

### 1.3 시장에서의 역할과 논쟁 (양면성)

| 긍정 | 부정/논쟁 |
|---|---|
| 유동성 공급 (마켓 메이킹) | "유령 유동성" — 시장 스트레스 때 증발한다는 비판 |
| bid-ask 스프레드 축소 → 거래비용 감소 | 2010 Flash Crash (다우 ~1000pt 급락 후 급반등) 등 변동성 증폭 논란 |
| 정보의 신속한 가격 반영 (price discovery) | 기술 군비경쟁 → 자본력 격차에 따른 불공정성 논쟁 |
| 시장 간 가격 수렴 (차익거래) | spoofing/quote stuffing 같은 조작 가능성 |

### 1.4 다른 트레이딩 스타일과의 비교

| 구분 | HFT | 데이 트레이딩 | 스윙 | 포지션 |
|---|---|---|---|---|
| 보유 기간 | 밀리초~초 | 분~하루 | 며칠~몇 주 | 몇 달~몇 년 |
| 하루 거래 수 | 수천~수백만 | 수십 | 소수 | 극소수 |
| 인프라 요구 | 극단적 (코로케이션 등) | 보통 | 낮음 | 낮음 |
| 핵심 리스크 | 시스템 장애, 미세 손실의 대량 누적 | 일중 변동 | 오버나이트/주말 갭 | 장기 시장 리스크 |

### 1.5 규제 지형 요약

- **미국**: SEC Market Access Rule(15c3-5) — 2010 플래시 크래시 이후 도입, 사전 리스크 컨트롤·감독 절차 의무화. CFTC는 선물 쪽 자동매매 규제(Reg AT 제안). Dodd-Frank의 Volcker Rule은 은행 자기매매 제한.
- **EU**: MiFID II/MiFIR — HFT 업체 인가제, 연간 자체평가 보고, 시스템 복원력 요건, 스트레스 상황에서의 마켓메이킹 의무, tick size regime(최소 호가 단위 규정).
- **아시아·태평양**: 일본 금융상품거래법(알고리즘 제출·검사), 호주 ASIC(주문 최소 유지 시간 — 과도한 취소 억제).
- 공통 테마: 투명성/공시, 시장 무결성, 시스템 리스크 관리(킬 스위치, 사전 리스크 체크), 공정 경쟁(코로케이션 동등 접근).

## Part 2. 시장 데이터와 실행 시스템 (Ch.2)

### 2.1 시장 데이터 3계층 — 이 책에서 제일 유용한 개념 정리

| 데이터 | 내용 | 용도 |
|---|---|---|
| **Level 1** ("top of the book") | 최우선 매수호가(bid)·매도호가(ask), 최근 체결가·체결량 | 시장 심리 스냅샷. 스프레드 폭 = 유동성/변동성 신호 |
| **Level 2** (market depth) | 호가창 전체 — 가격대별 잔량 | 수급 강도 파악, 주문 흐름 기반 단기 방향 예측 |
| **Tick-by-tick** | 모든 체결의 가격·수량·타임스탬프 | 최고 해상도. 미세 패턴 분석, 통계적 차익거래 캘리브레이션 |

### 2.2 데이터 정규화와 저장

- **정규화**: 거래소마다 타임스탬프 포맷, 소수점 자릿수, 심볼 표기가 제각각 → 통일 스키마(타임스탬프 해상도, 숫자 포맷, 식별자 표준)로 변환해야 분석이 왜곡되지 않음.
- **저장**: 속도(인메모리 DB, RAM) ↔ 영속성(SSD) ↔ 용량(샤딩으로 분산) ↔ 압축(저장 공간 절약 vs 해제 지연) 사이의 균형. 틱 데이터는 시계열 특화 DB(tick database)에.
- 정규화된 데이터는 균일해서 압축이 잘 됨 — 정규화와 저장 전략은 서로 영향을 주는 관계.

### 2.3 실행 시스템 3분할: OMS / EMS / DMA

- **OMS** (Order Management System): 주문 생애주기 관리 — 진입·검증·라우팅·상태 추적·규제 준수. 리스크 체크가 여기 통합됨.
- **EMS** (Execution Management System): 실제 시장 접점. 시장 상황에 따라 최적 실행 방법 결정(대량 주문 분할, 라우팅 경로 선택).
- **DMA** (Direct Market Access): 브로커 중개를 우회해 거래소 호가창에 직접 접속 → 실행 시간 단축의 핵심.

### 2.4 슬리피지(slippage) 대응 전략

슬리피지 = 기대 체결가와 실제 체결가의 차이. 고빈도로 누적되면 수익성을 갉아먹는 주범. 대응:

1. 실시간 유동성 분석 — 호가창 깊이로 시장 충격 예측, 주문 크기 조절
2. 주문 분할(fragmentation)과 iceberg 주문 — 실제 규모 은닉
3. 저지연 실행 자체 — 의도한 가격에 가깝게 체결
4. TWAP/VWAP 같은 평균가 추종형 주문 (Part 4에서 상세)
5. 슬리피지 실시간 모니터링 → 전략 자동 보정 피드백 루프

### 2.5 리스크 컨트롤: pre-trade / post-trade 이원 체계

- **Pre-trade (예방)**: 주문 검증(최대 수량, 시장가 대비 이탈 폭 체크), 포지션 한도, 지연 상태 점검. 체크 자체가 병목이 되면 안 되므로 초고속으로 구현해야 함.
- **Post-trade (사후)**: 실시간 P&L 모니터링, 규제 보고 자동화, 슬리피지 분석 → 결과를 pre-trade 파라미터 개선에 환류.
- 리스크 유형 분류: 시장 / 신용(거래상대방) / 유동성 / 운영(시스템 장애·버그·보안) / 법률·규제. 유형별로 대응이 다름 — 동적 헤징, 최적 실행, 이중화·페일오버, 컴플라이언스 모니터.

## Part 3. C++ 관련 내용 (Ch.3 + Ch.5 최적화 + 부록)

> 논문 정리본 Part 2와 겹치는 주제가 많음. 이 책은 기법을 "소개"만 하고 측정은 없으므로, 효과 수치는 논문 정리본을 참조할 것.

### 3.1 언어 비교 논리

- **vs Python**: 인터프리터 오버헤드 + GIL로 멀티스레딩 제약 → 리서치/프로토타이핑엔 좋지만 실행 경로엔 부적합.
- **vs Java**: GC의 비결정적 일시정지가 지연 스파이크 유발. (논문은 여기서 더 나아가 "GC를 끄고 사전 할당하면 Java도 가능"이라는 반례까지 다룸 — 논문 쪽이 더 균형 잡힘.)
- **vs R**: 통계·오프라인 분석 특화, 실시간 실행엔 부적합.
- **실무 패턴**: Python/R로 전략 리서치·백테스트 → C++로 라이브 실행 구현. 다언어 조합이 표준.

### 3.2 HFT 시스템의 표준 5모듈 구조

책 전체에서 반복되는 아키텍처 골격. 데이터가 흐르는 순서대로:

```
DataHandler → StrategyLogic → RiskManagement(체크) → OrderExecutionEngine
                                                          ↓
                              PerformanceMonitoring ← (체결 결과)
```

1. **Data Handler**: 시세 수신·파싱·정규화. 데이터 어댑터를 소스별로 상속 구현(다형성), 내부로는 통일 포맷 전달. 스레드 간 전달엔 lock-free 큐.
2. **Strategy Logic**: 신호 생성 (예: 이동평균, 모멘텀, 스프레드 기반).
3. **Order Execution Engine**: 거래소 프로토콜에 맞는 주문 생성·전송·응답 처리.
4. **Risk Management**: 사전 한도 체크, 손절, 노출 제한 — 실행 전 관문.
5. **Performance Monitoring**: 실행 지연, 슬리피지, 승률 등 KPI 수집 → 전략 개선 환류.

### 3.3 책이 꼽는 C++ 핵심 기능 (HFT 관점)

- **RAII**: 소켓·메모리 같은 자원을 객체 수명에 묶어 누수 방지 (시장 연결 관리에 예시).
- **템플릿/컴파일타임 일반화**: 런타임 오버헤드 없이 유연한 자료구조·알고리즘.
- **inline / constexpr**: 호출·계산을 컴파일 타임으로 이전. (실측 효과는 논문 정리본 2.3~2.4 참조)
- **Move semantics** (C++11): 대량 시장 데이터를 복사 없이 이전 — `std::move`로 소유권 이동.
- **동시성**: `std::thread`, futures, OpenMP, Intel TBB. 병렬화 3패턴 — 데이터 분할(data decomposition) / 태스크 병렬 / 파이프라인 병렬(수신→분석→실행 단계별).
- **저수준 접근**: 커스텀 메모리 할당, 하드웨어 특화 최적화.

### 3.4 성능 최적화 기법 카탈로그 (Ch.3 후반 + Ch.5)

논문과 겹치는 것들: 컴파일러 플래그(`-O3` — 단, 적용 후 반드시 재검증), loop unrolling, 벡터화/SIMD, 조건문 순서 배치(성공 확률 높은 조건을 앞에 → short-circuit 활용), `__builtin_prefetch`, 캐시 친화적 순차 접근, 프로파일링(gprof/Valgrind/perf) 후 병목 집중 공략.

책이 추가로 다루는 메모리 관리 레퍼토리:

| 기법 | 요지 |
|---|---|
| 스택 > 힙 | 힙 할당은 느리고 비결정적 → 가능하면 스택/사전 확보 |
| `reserve()` / `shrink_to_fit()` | 벡터 재할당 방지 / 미사용 용량 반환 |
| 스마트 포인터 | unique_ptr/shared_ptr/weak_ptr로 수동 관리 리스크 제거 |
| 커스텀 할당자 | 워크로드 특화 할당 패턴으로 단편화·오버헤드 감소 |
| **메모리 풀(object pool)** | 동일 크기 객체(주문 등)를 생성/파괴 반복하는 대신 풀에서 재사용 — 이 책에서 가장 실용적인 팁 중 하나. 논문의 "사전 할당 링 버퍼"와 같은 철학 |
| 메모리 맵 파일, 바이너리 직렬화 | 데이터 접근·저장 지연 축소 |

### 3.5 네트워크/인프라 레벨 (Ch.5 후반 + Ch.7)

- **TCP_NODELAY**: Nagle 알고리즘 비활성화 — 작은 패킷을 모아 보내는 지연을 제거. 소켓 옵션 한 줄로 되는 대표적 저지연 설정:
  ```cpp
  int yes = 1;
  setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &yes, sizeof(yes));
  ```
- InfiniBand(이더넷 대비 고대역·저지연), 전용 저지연 NIC, DMA 연결, 코로케이션.
- FPGA(알고리즘을 하드웨어에 직접 구현, 나노초 단위)와 GPU(대규모 병렬 계산) 역할 구분.
- **PTP**(Precision Time Protocol)로 시스템 간 시계 동기화 — 정확한 타임스탬프는 규제 요건이기도 함.
- 커스텀/경량화 Linux 또는 RTOS(실시간 OS)로 OS 오버헤드 제거.

## Part 4. 퀀트 모델과 트레이딩 전략 (Ch.4 + 부록)

### 4.1 모델 개발 파이프라인 (5단계)

데이터 수집·전처리(정규화, 결측·이상치 처리) → 피처 선택(예측력 있는 지표 추출) → 모델 개발 → **백테스트** → 최적화(파라미터 조정). 이 순환을 반복. 이 책에서 몇 안 되는 체계적인 프레임.

### 4.2 통계 모델 스펙트럼

| 모델 | 성격 | 비고 |
|---|---|---|
| 선형회귀(OLS) | 장기 추세 파악의 기초 | C++에선 Eigen 라이브러리로 행렬 연산 |
| AR(p) 자기회귀 | 과거 p개 시점으로 미래 예측 — 모멘텀 포착 | |
| ARIMA / GARCH | 추세·계절성 있는 시계열 / 변동성 군집 모델링 | 직접 구현보다 QuantLib 같은 라이브러리 활용 권장 |
| ML (SVM, 신경망, 앙상블) | 비선형 패턴 포착 | dlib, MLPACK, Shark; 딥러닝은 TensorFlow/PyTorch C++ 인터페이스 |
| 강화학습 | 시장과 상호작용하며 전략 자체를 학습 | 관찰→행동(매수/보유/매도)→보상으로 조정하는 에이전트 구조 |
| NLP 감성 분석 | 뉴스·SNS 텍스트에서 시장 심리 추출 | C++ 단독보단 외부 라이브러리/API 연동 |

### 4.3 실행 알고리즘 3종 — VWAP / TWAP / Iceberg

대량 주문을 시장에 들키지 않고 흘리는 기술. 책에서 실무적으로 가장 쓸모 있는 부분:

- **VWAP** (Volume-Weighted Average Price): 거래량 가중 평균가에 근접하게 실행. 유동성이 높을 때 더 많이 거래 → 거래량 패턴이 뚜렷한 시장에 적합.
- **TWAP** (Time-Weighted Average Price): 시간 구간에 균등 분산 실행. 거래량 패턴이 예측 불가하거나 변동성이 클 때.
- **Iceberg**: 전체 수량 중 일부("빙산의 일각")만 호가창에 노출, 체결되면 다음 조각 자동 공개. 저유동성 시장에서 대량 주문의 시장 충격 최소화.

**선택 로직**: 시장 상태(변동성·거래량 패턴·유동성) × 주문 특성(크기·긴급도·가격 민감도) × 전략 목표(비용 최소화 vs 실행 확실성). 정적 선택이 아니라 실행 중에도 시장 분석에 따라 알고리즘을 갈아타는 **적응형 선택**이 이상적 — 예: 저유동성에서 Iceberg로 시작 → 유동성 패턴 확인 후 VWAP 전환.

### 4.4 HFT 전략 카탈로그 (부록)

합법적 전략: 마켓 메이킹(스프레드 수익), 차익거래(공간적 — 시장 간 가격차 / 통계적 — 모델 기반 상대가격 / 삼각 — 3개 통화 간), 모멘텀, 이벤트 차익거래(M&A·발표 선반응), 인덱스 리밸런싱 선취, 뉴스 기반, 틱 데이터 패턴 분석.

⚠️ **불법/조작으로 분류되는 것** (책도 명시): **quote stuffing**(대량 주문 후 즉시 취소로 시장 교란), **layering/spoofing**(체결 의도 없는 주문으로 가격 유도). 규제기관이 시장 조작으로 처벌하는 행위 — "전략 목록"에 섞여 있지만 절대 같은 범주가 아님. flash order도 다수 관할권에서 제한됨.

### 4.5 실시간 전략 조정

이벤트 기반 트리거(변동성·호가 불균형·뉴스가 임계값 돌파 시 전략 재보정) + 피드백 루프(과거 조정의 결과를 학습) + 리스크 관리 연동(공격적 조정이 노출 한도를 넘지 않게). 핵심 난제는 **노이즈와 진짜 국면 전환의 구분** — 일시적 요동에 과잉 반응하면 오히려 손해. 이 책의 답은 "임계값 기반 유의성 판정"이지만 구체적 방법론은 없음(한계).

## Part 5. 파라미터 최적화와 확장성 (Ch.5)

### 5.1 파라미터 최적화 기법 계보

- 기본: **grid search / random search** — 파라미터 공간의 체계적/무작위 탐색.
- 진화형: **유전 알고리즘(GA)** — 선택→교차→변이 세대 반복으로 좋은 파라미터 조합 탐색. 병렬화 잘 됨.
- 확률형: **베이지안 최적화** — 개선 가능성 높은 영역에 탐색 자원 집중.
- 연속 파라미터: **경사 기반**(SGD 등).
- 기타 메타휴리스틱: **Simulated Annealing**(담금질 — 국소 최적 탈출에 유리), **PSO**(입자 군집 — 비선형 문제에 적합).
- **다목적 최적화**: 수익률·드로다운·Sharpe가 서로 상충할 때 — Pareto 최적 집합(한 목표를 개선하려면 다른 목표가 나빠지는 경계) 또는 가중합 모델로 접근.

### 5.2 과적합 vs 과소적합 — 이 책이 가장 강조하는 함정

- **과적합**: 과거 데이터의 노이즈까지 학습 → 백테스트 완벽, 실전 붕괴.
- **과소적합**: 너무 단순해서 패턴 자체를 못 잡음 → 백테스트부터 부진.
- 대응: **k-fold 교차검증**, **out-of-sample 테스트**(개발에 안 쓴 데이터로 검증), 정규화(regularization — 복잡도에 벌점), 피처 선택(예측력 있는 지표만), **앙상블**(bagging/boosting으로 분산·편향 동시 억제), **walk-forward 분석**(in-sample 최적화 → 직후 구간 out-of-sample 검증을 굴려가며 반복).

### 5.3 확장성(scalability) 전략

- 스레드 풀 + 뮤텍스/condition_variable 기반 주문 큐 → 멀티코어 분산 처리. (논문의 Disruptor는 바로 이 구조의 락 오버헤드를 제거한 상위 호환 — 상호참조)
- **데이터 파티셔닝**: TBB `parallel_for_each` 등으로 시장 데이터를 청크 단위 병렬 처리.
- 단일 머신 한계 초과 시 **분산 컴퓨팅**: Kafka(데이터 분배) + Spark(분산 처리) + 성능 크리티컬 구간만 C++ 조합.
- 동적 자원 배분: 커스텀 할당자, TBB/MPI 기반 로드 밸런싱, 프로파일링 기반 조정.

## Part 6. 리스크·컴플라이언스 심화 (Ch.6)

- **한도 설정의 3층위**: 동적 임계값(변동성·유동성·자기 성과 이력에 따라 실시간 조정) / 미시 포지션 한도(단일 자산 과노출 방지 — 일부 거래가 망해도 전체 피해 격리) / 시간 기반 한도(저유동성·고불확실성 시간대 거래 제한).
- **손실 방지 장치**: 실시간 리스크 대시보드 + 임계 돌파 알림, **kill switch**(이상 행동 감지 시 전체 거래 즉시 중단 — 폭주 알고리즘·플래시 크래시 대비 필수 장치), 전략·시장·시간대 분산.
- **스트레스 테스트 / 시나리오 분석**: 과거 폭락 모델, 변동성 급등 + 유동성 50% 증발 같은 극단 조건을 시뮬레이션해 전략의 파단점 확인.
- **유동성 관리의 이중 역할**: HFT는 유동성의 소비자이자 공급자. 수동적(지정가 제시) + 능동적 마켓메이킹 병행, 시장 상황 예측에 따른 동적 유동성 공급 조절.
- 헤징(파생상품으로 실시간 반대 포지션), 정량 리스크 모델(과거 데이터 기반 손실 분포·확률 추정).

## Part 7. 시스템 아키텍처·하드웨어 (Ch.7)

### 7.1 설계 3원칙

**저지연**(모든 구간 최적화) / **확장성**(볼륨 증가에도 성능 유지) / **신뢰성**(무중단). 여기에 설계 전술로: 단순성(복잡성 = 지연), 모듈화(지연 지점 격리·교체 용이), 데이터 지역성(관련 데이터를 붙여 저장), 인메모리 컴퓨팅, 마이크로서비스식 분할.

### 7.2 하드웨어 선택 기준

| 부품 | 핵심 기준 |
|---|---|
| CPU | 클럭 속도 + 코어 수(병렬) + 캐시 크기. "빠른 것"보다 워크로드 적합성 |
| GPU | 수천 스레드 동시 처리 — 계산 집약 모델에 |
| FPGA | 특정 알고리즘을 회로로 — 나노초급, pre-trade 체크·피드 처리에 |
| NIC/스위치 | 저지연 특화 장비, DMA 지원 |
| SSD + 고속 RAM | 데이터 접근 지연 최소화 |
| 냉각 | 발열로 인한 thermal throttling 방지 — 의외로 성능 요소 |

### 7.3 소프트웨어 스택: 상용 vs 오픈소스

- **상용(proprietary)**: 맞춤 개발·전담 지원·컴플라이언스 기능 ↔ 비용, 벤더 종속, 배포까지 시간.
- **오픈소스**: 무료·수정 자유·커뮤니티 혁신 ↔ 공식 지원 부재, 보안·규제 요건 자체 검증 부담, 품질 편차.
- 실무 답: **하이브리드** — 오픈소스 기반 위에 자체 커스텀 레이어. 전략적 우선순위(혁신 속도 vs 비용 vs 독점 우위)와 보유 역량에 따라 결정.

## Part 8. 테스트 → 배포 → 운영 (Ch.8~9)

### 8.1 백테스팅의 4대 데이터 품질 요건

**완전성**(갭 없이 모든 체결·호가 포착) / **세밀도**(ms 이하 타임스탬프) / **정확성**(실제 시장 반영) / **정규화**(시대·소스 간 일관 포맷). 데이터 품질이 곧 백테스트 신뢰도의 상한. 데이터 부패(data decay — 시장 진화로 과거 데이터의 대표성 하락), 정제(오류 체결·중복 제거), 비용·접근성 문제까지 관리 대상.

### 8.2 백테스트 정확도를 높이는 기법

- **Monte Carlo 시뮬레이션**: 가격·체결에 무작위 변형을 넣어 다양한 시나리오에서 강건성 확인 (과거 재생만으론 못 보는 조건 탐색).
- **슬리피지·거래비용 모델링**: 마진이 얇은 HFT에서 이걸 빼면 백테스트가 장밋빛 왜곡됨.
- **walk-forward 분석**, out-of-sample 확보, 벤치마크 대비 평가, 민감도 분석(입력 미세 변화에 결과가 요동치면 취약한 전략).
- 시장 시뮬레이션의 난제: 시장 미시구조의 거래소별 차이, 뉴스 이벤트의 돌발성, 참여자 전략의 공진화, 호가창 상태 재구성, 지연의 정확한 재현.

### 8.3 실시간 시뮬레이션과 스트레스 테스트

백테스트(과거) 다음 단계 — **paper trading**(라이브 데이터에 연결하되 실제 주문 없이), 가상 시장 참여자 봇, **지연 주입**(네트워크·처리·체결 지연을 일부러 재현). 스트레스 시나리오: 급락/급등, 초대량 거래, 운영 장애(피드 단절·네트워크·하드웨어) 주입 → 우아한 실패(fail gracefully) 또는 신속 복구 확인.

### 8.4 배포: 단계적 롤아웃이 철칙

```
paper trading (모의) → 소규모 실거래 (자본 일부) → 점진 확대 → 전체 배포
```

초기엔 검증된 기존 전략과 **병렬 운영**(parallel run)으로 성과 비교. 사전 체크리스트: 코드 리뷰·알고리즘 무결성, 지연 측정, 데이터 피드 정확성, 인프라 스트레스 테스트, 규제 승인·컴플라이언스, 자본 배분·리스크 파라미터·예비 자금, 운영팀·재해복구 계획·비상 연락 체계.

### 8.5 운영 모니터링

- 실시간 대시보드: 지연, 에러율, 처리량, 승률, 슬리피지, P&L 등 KPI.
- 세분화된 알림 체계 + **kill switch** 상시 대기.
- 이상 탐지(anomaly detection)로 알고리즘 폭주 조기 발견, 이중화 데이터 피드.
- CI/CD 파이프라인으로 전략 수정을 자동 테스트 거쳐 반영.
- ML 예측 모니터링(장애 징후 선제 감지), 클라우드 활용(스케일링·재해복구)도 언급.

### 8.6 사후 분석 (post-trade analysis)

- **TCA**(Transaction Cost Analysis): 수수료 같은 명시적 비용 + 슬리피지 같은 암묵적 비용 종합 분석.
- 실행 품질 지표: 체결가 vs 시장가, 체결률, 체결 소요 시간.
- **market replay simulator**: 체결 시점의 시장 상태를 재생해 의사결정 사후 검증.
- 정량 분석 + 시각화(히트맵, 시계열) + 행동 편향 분석까지 → 결과를 전략 개발에 자동 환류(ML 모델에 재투입).

### 9.3 샘플 프로그램의 실체

부록의 "HFT 프로그램 만들기"는 컴파일러 설치 + Hello World 수준이고, 샘플 마켓메이커도 `midPrice ± spread/2`로 호가를 갱신하는 골격(주문 API는 전부 빈 함수). 학습 가치는 "마켓메이킹 루프의 최소 형태"를 보는 정도: 시세 수신 → 중간가 계산 → 기존 주문 취소 → 새 매수/매도 지정가 제출 반복.

## 부록 B. 추가 용어 (논문 정리본 용어집에 없는 것만)

| 용어 | 뜻 |
|---|---|
| Level 1 / Level 2 / tick data | 최우선호가 / 호가창 전체 / 전 체결 기록 |
| OMS / EMS / DMA | 주문 관리 / 실행 관리 / 거래소 직접 접속 |
| Slippage | 기대 체결가와 실제 체결가의 차이 |
| VWAP / TWAP | 거래량/시간 가중 평균가 추종 실행 알고리즘 |
| Iceberg order | 일부만 노출하는 대량 주문 |
| Spoofing / Layering / Quote stuffing | 체결 의도 없는 주문·대량 취소로 시장을 속이는 불법 조작 |
| Kill switch | 이상 감지 시 전체 거래 즉시 중단 장치 |
| Paper trading | 실주문 없이 라이브 데이터로 모의 운용 |
| Walk-forward 분석 | 최적화 구간과 검증 구간을 굴려가며 반복하는 과적합 방지 검증 |
| TCA | 거래 비용(명시적+암묵적) 종합 분석 |
| PTP | 정밀 시간 동기화 프로토콜 |
| FIX protocol | 전자 거래 메시지 표준 (QuickFIX가 대표 구현) |
| Algorithmic decay | 시장 적응·경쟁으로 전략 효과가 시간에 따라 감쇠하는 현상 |
