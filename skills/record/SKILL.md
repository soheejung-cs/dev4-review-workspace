# 기록 규약 (record)

**한 발견은 한 곳에만** 둔다. 어디로 가는지 헷갈리면 아래 판단표.

## 0. 판단표 — 이 발견은 어디로?
| 발견의 성격 | 어디 | 형식 |
|---|---|---|
| 리뷰 답글 원문, 설계 리뷰 덱, 재현 스크립트, 결정 상태 | `claude-workspace/projects/CBRD-XXXXX/` (**프로젝트 디렉터리는 옮기지 않는다**) | `세션기록-YYYYMMDD.md`, `repro/*.sh`, `설계리뷰-덱.html`, `prNNNN_*.md` |
| **검증된 코드 사실**(함수 계약, 락 수준, 카탈로그 스키마, 함정) | `dev4-ai-source/staging/환류대기.md` → 모듈 `§2·§3` | 출처 컨테이너 + 기준 리비전, 미수정 상태 명시 |
| **일하는 방식**(재현 순서, 문체, 사용자 지시) | 리뷰 방식이면 **이 리포 `skills/*/SKILL.md`**, 그 외는 `claude-workspace/memory/rules|howto` | 지시 날짜와 Why |
| 재발 방지가 중요한 **환경 함정** | `claude-workspace/공통-CLAUDE.md` 함정 절(세 컨테이너 공통) 또는 `hosts/<ip>.md` | 실측 날짜·컨테이너 |
| 진행 상태 | agent-todo 보드 카드 코멘트 + `worklog: YYYY-MM-DD` 1줄 | `- [영역] 한 일 (링크) — session_ID앞8자` |
| 설계·분석 문서 | `projects/CBRD-XXXXX/설계문서.md` (+ `projects/현황.md` 행) | `projects/문서규약.md` |

## 1. `세션기록-YYYYMMDD.md` 형식
```
# CBRD-XXXXX / PR#n — 세션 기록 (기간, 컨테이너)
## 한 일 (커밋 순)      | 커밋 | 내용 |  — TC 커밋도 포함
## 검증                시나리오·빌드(release/debug)·CTP 결과·미규명 관측("원인 미규명 — 다음에 X 부터 본다")
## 리뷰 대응            스레드 수·게시 방식·덱 링크
## 결정 상태            Q 표 (미결/추천/사용자 결정)
## 남은 일
```

## 2. 소스 사실을 적는 형식 (`dev4-ai-source/staging/환류대기.md`)
```
- **[모듈 §2|§3] 한 줄 주장** (컨테이너, 기준 리비전, 날짜): 근거(함수·줄·실측). 미수정이면 **미수정** 표시.
```
하루 1회 모듈 파일 §2·§3 로 옮기고 대기소에서 지운다(중복 금지). 소스 *구조* 는 엔진 `AGENTS.md` 가 1차 정본 — 거기 있으면 쓰지 않는다.

## 3. 세션을 끊을 때 (사용자 "하던 작업 중단하고 기록해")
1. 진행 중이던 백그라운드(빌드·CTP·모니터)를 멈추고 상태를 한 줄로 적는다(코어 여부, 어디서 멈췄나).
2. `세션기록` 갱신 → 소스 사실 대기소 → 방식 학습(스킬/메모리) → 보드 코멘트 + worklog → 리포 3개 commit·push.
3. 남은 일을 **결정이 필요한 것 / 그냥 하면 되는 것**으로 나눠 마지막 보고에 적는다.

## 4. 하지 않는 것
- 아티팩트 재게시로 기록을 대신하지 않는다(사용자 명시 허용 시만 아티팩트).
- 프로젝트 문서를 엔진 리포에 커밋하지 않는다.
- 같은 사실을 메모리와 소스 노트 양쪽에 적지 않는다.
